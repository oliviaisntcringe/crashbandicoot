# AES-ECB Leak — карта плейнтекста без ключа

---

## Почему ECB уязвим к статистическому анализу

В режиме ECB каждый 16-байтный блок шифруется **независимо одним и тем же ключом**:

```
E(key, block_1) → cipher_1
E(key, block_2) → cipher_2
...
E(key, block_N) → cipher_N

Если plaintext_i == plaintext_j  →  cipher_i == cipher_j
```

В прошивке DVR много нулевых байт (неинициализированная flash, выравнивания, разделы).  
Все эти блоки дают **одинаковый шифртекст** — без ключа.

---

## Нахождение «сигнатурного блока»

```python
from collections import Counter

with open('digicap.dav', 'rb') as f:
    f.seek(124)          # пропустить HK20 + HK30 заголовки
    body = f.read()

blocks = [body[i:i+16] for i in range(0, len(body) - len(body)%16, 16)]
cnt    = Counter(blocks)

top3 = cnt.most_common(3)
for block, count in top3:
    print(f"  {block.hex()}  ×{count}")
```

Результат:
```
  b311020e...  ×40 065   ← шифр нулей  (640 KB нулевого плейнтекста)
  a7f2c1...    ×12       ← повтор другой структуры
  ...
```

## Восстановление карты разделов

```python
ZERO_BLOCK = top3[0][0]   # самый частый блок

# Построить bitmap: 1 = нулевой блок, 0 = данные
bitmap = [1 if blocks[i] == ZERO_BLOCK else 0
          for i in range(len(blocks))]

# Посчитать плотность нулей по окнам
window = 1000   # блоков × 16 байт = 16 KB окно
density = [sum(bitmap[i:i+window])/window
           for i in range(0, len(bitmap), window)]
```

По плотности нулей можно восстановить **границы разделов flash** — без расшифровки.

## Практическое применение

### Нашли без ключа:

1. **Структуру разделов** — где заканчивается kernel, где начинается rootfs
2. **Тип прошивки** — DVR класс 1, version `3050060061181310011`
3. **Plaintext footer** — "ation" (хвост copyright строки)
4. **Hardcoded IP** в JS-скриптах — `172.9.4.222` (найден в HTTP-ответах, не в прошивке)

### Что нужно для полного доступа:

```
AES-256 ключ → расшифровать тело → извлечь бинарники →
grep '\x10\xff\x2f\xe1' rtsp_daemon → BX R0 адрес → RCE
```

Ключ, по всей видимости, хранится в другом бинарнике на устройстве  
(например в `libhikvision.so` или `update_helper`) — недоступен без RCE.
